Транспорт QUIK# (shm / tcp)
==========

QUIK# умеет обмениваться данными между Lua-скриптом в QUIK и .NET-клиентом двумя
способами. Выбор — один на весь скрипт, оба сразу работать не могут.

- **shm** (по умолчанию) — shared memory + именованные семафоры
  (`Transports/ShmQuikTransport.cs` + `lua/qsutils.lua`). Быстрее, не требует открытых
  портов. Минус: если .NET-клиент или сам QUIK упадёт в момент удержания
  семафора-мьютекса, второй участник зависает без таймаута — QUIK может перестать
  отвечать.
- **tcp** ("netstack") — два TCP-сокета: Lua-скрипт слушает как сервер, .NET
  подключается как клиент (`Transports/TcpQuikTransport.cs` + `lua/nettransport.lua`).
  Не подвешивает QUIK при обрыве связи (сокет просто закрывается), но зависит от того,
  что вендоренная LuaSocket (`lua/clibs*/.../socket/core.dll`) совпадает по версии
  Lua/разрядности с вашей версией QUIK — из-за этого иногда не запускается.

Как переключить транспорт
--------------------------

1. Откройте `lua/config.json`.
2. Поменяйте верхнеуровневое поле `"transport"`:

    ```json
    {
        "transport": "tcp",
        "servers": [ ... ]
    }
    ```

    Допустимые значения — `"shm"` или `"tcp"`. Если поля нет вообще — используется
    `"shm"` (прежнее поведение, ничего не ломается, если конфиг не трогать).

3. Перезапустите Lua-скрипт в QUIK (остановить/запустить `QuikSharp.lua`, либо
   перезапустить сам терминал).
4. В C#-коде менять ничего не нужно: `Program.cs` и `QS.Tests/Program.cs` через
   `TransportFactory.ReadFromDefaultConfig()` сами читают тот же `lua/config.json`
   и поднимают нужный транспорт.

Порты для tcp-режима
---------------------

Берутся из той же секции `servers`, что раньше использовалась для подключения к
нескольким терминалам (см. `USAGE.RU.md`):

```json
{
    "transport": "tcp",
    "servers": [
        {
            "scriptName": "QuikSharp",
            "responseHostname": "127.0.0.1",
            "responsePort": 34130,
            "callbackHostname": "127.0.0.1",
            "callbackPort": 34131
        }
    ]
}
```

- `responsePort` — запросы/ответы.
- `callbackPort` — отдельный порт для коллбэков (обычно `responsePort + 1`).
- Порты должны быть свободны на localhost и не блокироваться файрволом.

Что происходит при старте в tcp-режиме
----------------------------------------

- Lua-скрипт биндит оба серверных сокета и дальше не блокируется: если QUIK
  запустился раньше .NET-клиента, скрипт просто ждёт подключения, ошибок нет.
- .NET-клиент пытается подключиться к обоим портам в течение 30 секунд (повтор
  каждые 500 мс) — если Lua-скрипт ещё не поднялся, клиент подождёт, а не зависнет.

Как проверить, какой транспорт реально используется
-------------------------------------------------------

- В логе QUIK при старте скрипта: `QUIK# (tcp): listening on 127.0.0.1:34130 ...`
  для tcp, либо обычное сообщение про shared memory для shm.
- То же самое — в файле `lua/logs/QUIK#_ГГГГММДД.log`.
- В `QS.Tests/Program.cs` при запуске печатается `Инициализация транспорта: {Shm|Tcp}...`.

Когда что выбирать
--------------------

- По умолчанию используйте `shm` — быстрее и не требует открытых портов.
- Если QUIK стал зависать/переставать отвечать без явной причины — попробуйте `tcp`
  и посмотрите, повторяется ли проблема.
- Если `tcp` не запускается (в логе `module 'socket' not found`) — проверьте, что
  версия и разрядность QUIK соответствуют одной из папок `lua/clibs(64)/*_M*`
  (см. блок определения `libPath` в начале `QuikSharp.lua`).
